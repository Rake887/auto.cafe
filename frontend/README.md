# Гостевой фронтенд QR-меню

Next.js 16 (App Router, SSR), TypeScript, Tailwind v4. Экраны гостя — меню,
корзина, статус заказа — и кабинет владельца: статистика, ведение меню,
QR-коды столов для печати.

Меню рендерится на сервере: гость на мобильном интернете видит блюда почти
сразу, без ожидания клиентского запроса за данными.

## Запуск

В составе всего стека (Docker, из корня репозитория) — см.
[../README.md](../README.md):

```bash
docker compose up -d --build
```

Отдельно, для работы над кодом:

```bash
npm install
npm run dev          # http://localhost:3000
```

Страница меню: `/m/{token}`, где token — токен стола из сидинга бэкенда
(`docker compose --profile tools run --rm seed`). Стартовая `/` — служебная,
с QR-кодом демо-стола и ссылкой на экран ошибки неверного QR.

## Переключение мок / реальный бэкенд

```
# .env.local
NEXT_PUBLIC_API_BASE=http://localhost:8010   # реальный FastAPI
# переменная пустая или отсутствует           # мок-данные из src/lib/mock.ts
NEXT_PUBLIC_DEMO_TOKEN=demo                  # токен стола для кнопки на «/»
```

Вся работа с сетью изолирована в [src/lib/api.ts](src/lib/api.ts) —
`fetchMenu`, `createOrder`, `fetchOrderStatus`, `callWaiter` и ручки админки.
Адреса там два: `NEXT_PUBLIC_API_BASE` для браузера гостя и
`INTERNAL_API_BASE` для SSR (в Docker это `http://api:8000`, вне контейнера
переменная не нужна — берётся публичный адрес).

Мок-слой ([src/lib/mock.ts](src/lib/mock.ts)) повторяет контракт бэкенда 1:1,
включая идемпотентность заказа и антиспам вызова официанта. Токен `invalid`
отдаёт 404 — так проверяется экран неверного QR.

## Дизайн-система

Пресет «Кофейня» — единственный в MVP. Токены в
[src/app/globals.css](src/app/globals.css) в два слоя: примитивы палитры в
`:root`, семантические токены в `@theme`. Компоненты используют **только**
семантические (`bg-surface`, `text-ink`, `bg-accent`) — благодаря этому
остальные пресеты добавятся переопределением примитивов, без переписывания
компонентов.

Шрифты: заголовки **PT Serif**, текст **Manrope**, оба самохостятся через
`next/font` — ноль сетевых запросов в рантайме. PT Serif выбран вместо
Cormorant намеренно: у Cormorant неполная кириллица и нет казахских глифов
`ә ғ қ ң ө ұ ү һ і`, на локали `kk` заголовки бы ломались.

Учтены мелочи мобильных экранов: шапка и липкие табы используют
`env(safe-area-inset-top)`, поэтому контент не заезжает под вырез; последняя
короткая категория подсвечивается в табах у самого низа страницы, где
`IntersectionObserver` её уже не ловит; все анимации под `motion-safe` и
уважают системную настройку «уменьшить движение».

## Языки

Русский и казахский: словарь в [src/lib/i18n.ts](src/lib/i18n.ts), без
библиотек — строк несколько десятков. Язык берётся из `?lang=kk` (чтобы у
SSR-кэша были разные ключи) и запоминается в cookie. Переведены надписи
интерфейса; названия и описания блюд остаются такими, какими их ввело
заведение.

## Экраны

| Путь | Что это |
|---|---|
| `/m/{token}` | меню стола: липкие табы, «+» прямо в списке, вызов официанта |
| `/order/{id}?t={token}` | статус заказа, поллинг раз в 4 сек до «обслужен» |
| `/admin/login` | вход владельца по логину и паролю |
| `/admin` | статистика: выручка, топ блюд, часы пик, работа персонала |
| `/admin/menu` | ведение меню: цены, стоп-лист, фото, порядок, импорт CSV |
| `/admin/qr` | QR-коды столов, вёрстка под печать |
| `/` | служебная страница показа с QR демо-стола |

## Кэш меню

`fetchMenu` кэширует ответ на 20 секунд и помечает его тегом. После правки в
админке кэш сбрасывается через Route Handler
[src/app/revalidate/route.ts](src/app/revalidate/route.ts) — гость видит новую
цену с первого же запроса. Путь намеренно не под `/api`: этот префикс прокси
отдаёт бэкенду.

Важно: сброс сделан через `revalidateTag(tag, { expire: 0 })`. Рекомендованный
документацией профиль `"max"` даёт stale-while-revalidate — владелец правит
цену, обновляет страницу гостя и снова видит старую, что выглядит как поломка.
